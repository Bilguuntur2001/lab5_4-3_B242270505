## Тест дизайны 5 алхам (Лекц 5)

### 1. Бие даан тестлэгдэх функц

`POST /registrations` нь `{studentID, courseID}` хүлээн авч оюутныг хичээлд бүртгэнэ. Энэ функцийн үр дүнд нөлөөлөх төлөв нь `PUT /students/:id` болон `PUT /courses/:id`-ээр тавигддаг.

### 2–3. Сонголтууд ба төлөөлөх утгууд (эквивалент ангиуд)

| # | Сонголт (parameter / орчин) | Анги | Төлөөлөх утга |
|---|---|---|---|
| A | studentID-гийн хүчинтэй байдал | A1 идэвхтэй | `PUT /students/X {"status":"active"}` |
| | | A2 идэвхгүй | `{"status":"inactive"}` |
| | | A3 байхгүй | бүртгэгдээгүй ID (`B_NOPE_…`) |
| | | A4 талбар дутуу [хязгаар] | body-д `studentID` байхгүй |
| B | Оюутны үзсэн хичээлүүд | B1 урьдач нөхцөлийг хангана | `["CS201"]` |
| | | B2 хангахгүй | `["MATH101"]` |
| | | B3 хоосон [хязгаар] | `[]` |
| C | courseID-гийн хүчинтэй байдал | C1 байгаа | `PUT /courses/X` хийсэн |
| | | C2 байхгүй | бүртгэгдээгүй ID |
| | | C3 талбар дутуу [хязгаар] | body-д `courseID` байхгүй |
| D | Хичээлийн урьдач нөхцөл (оюутны үзсэнтэй харьцуулахад) | D1 бүгдийг үзсэн | prereq `["CS201"]`, үзсэн `["CS201"]` |
| | | D2 огт үзээгүй | prereq `["CS201"]`, үзсэн `[]` |
| | | D3 зарим нь | prereq `["CS201","CS202"]`, үзсэн `["CS201"]` |
| | | D4 урьдач нөхцөлгүй [хязгаар] | prereq `[]` |
| E | Хүсэлтийн формат | E1 зөв JSON | — |
| | | E2 буруу JSON [хязгаар] | `{bad json` |

**Боломжгүй / утгагүй хослолууд:**
- **A3 (оюутан байхгүй) × B\*:** байхгүй оюутанд "үзсэн хичээл" гэж байхгүй.
- **C2 (хичээл байхгүй) × D\*:** байхгүй хичээлд урьдач нөхцөл байхгүй.
- **A4/C3/E2 × бусад бүх анги:** хүсэлт форматын шатанд (400) татгалзагддаг тул бусад сонголт хэзээ ч шалгагдахгүй.

Эдгээрийг тус бүрд нь нэг л тестээр төлөөлүүлсэн.

### 4. Спецификациуд (12)

Стратеги: happy path 1, алдааны анги бүрд 1 (4), давхар алдааны хослол 2, хязгаарын тохиолдол 5.

| # | Төрөл | Хослол | Хүлээгдэх статус | Хүлээгдэх `result` |
|---|---|---|---|---|
| S01 | Happy path | A1, B1, C1, D1 | **201** | `OK` + `registrationID` нь тоо |
| S02 | Алдаа | A3 | 200 | `ERROR_NO_STUDENT` |
| S03 | Алдаа | A2, C1 | 200 | `ERROR_INACTIVE_STUDENT` |
| S04 | Алдаа | A1, C2 | 200 | `ERROR_NO_COURSE` |
| S05 | Алдаа | A1, B3, D2 | 200 | `ERROR_PREREQUISITES`, `missing = ["CS201"]` |
| S06 | Давхар алдаа | A3 + C2 (оюутан ч, хичээл ч байхгүй) | 200 | `ERROR_NO_STUDENT` (оюутныг эхэлж шалгадаг) |
| S07 | Давхар алдаа | A2 + D2 (идэвхгүй ба урьдач дутуу) | 200 | `ERROR_INACTIVE_STUDENT` |
| S08 | Хязгаар | D3 (зарим нь үзсэн) | 200 | `ERROR_PREREQUISITES`, `missing = ["CS202"]` |
| S09 | Хязгаар | A1, B3, D4 (prereq байхгүй, хоосон coursesTaken) | **201** | `OK` |
| S10 | Хязгаар | C3 (`courseID` дутуу) | **400** | `ERROR_BAD_REQUEST` |
| S11 | Хязгаар | A4 (`studentID` дутуу) | **400** | `ERROR_BAD_REQUEST` |
| S12 | Хязгаар | E2 (буруу JSON) | **400** | `ERROR_BAD_JSON` |

Давхар алдааны үед аль хариу буцахыг зааварт тусгаагүй. Тиймээс S06 болон S07-оор шалгах дарааллыг тогтоосон: оюутан → идэвхтэй эсэх → хичээл → урьдач нөхцөл.
